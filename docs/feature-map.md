# Feature map

One row per CLI command and web page: what it does, what it reads and writes, and what an
external API call costs per run. Derived from the code — when a cost depends on the data, it
says "varies". Ad-account writes happen only through `pnpm meta-ads` write subcommands, each
journaled to `meta_ads_changes` and requiring a `--plan` document name.

## CLI commands

| Command | What it does | Reads/writes | Tables touched | External API cost per run |
|---|---|---|---|---|
| `pnpm product list` / `show` | List/show products and their tracked sources | DB read | `products`, `tracked_sources` | 0 |
| `pnpm product create` / `update` | Create/update a product profile | DB write | `products` | 0 |
| `pnpm product docs list` / `import` / `add` / `show` / `export` | List, import, add, read and export typed product documents | DB read/write | `product_docs` | 0 |
| `pnpm product delete` | Delete a product and everything linked | DB write (destructive) | `products`, `tracked_sources`, linked rows | 0 |
| `pnpm product add-source` / `remove-source` / `enable-source` / `disable-source` | Manage a product's tracked sources | DB write | `tracked_sources` | 0 |
| `pnpm scrape` | Scrape a product's enabled ad sources (Ad Library) and store ads + media | DB write | `ads`, `creatives`, `ad_creatives`, `product_ads`, `scrape_runs`, `ad_library_observations` | varies (ScrapeCreators credits or Playwright; see --help) |
| `pnpm social` | Sync organic account + post stats per product | DB write | `social_accounts`, `social_account_snapshots`, `social_posts`, `social_post_media`, `social_post_snapshots`, `creatives` | varies (--posts/--max-credits; ScrapeCreators ~1 credit per profile + 1 per 10 Facebook reels; `--since` bounds a Facebook backfill) |
| `pnpm b2b-social add\|sync\|enrich\|import` | B2B Social: `add` watches an X account or a LinkedIn page or profile (group company, team or competitor; `--off`/`--on`, `--reset`, and X reply cap/order); `sync` fetches new posts and due comments for optional comma-separated `--group` values, then enriches commenter profiles and eligible people with Exa; `--posts-only` stops after new posts; `--dry-run` estimates X reply spend per account and total at most from stored reply counts and each account's 10–100 cap. `enrich` runs only the Exa step for stored people, with `--dry-run`, `--limit` and `--max-exa-usd`. `import --file` loads a local snapshot | DB write | `tracked_sources` (source `b2b_social`), `b2b_posts`, `b2b_comments`, `b2b_people`, `scrape_runs` | ScrapeCreators ~1 credit per LinkedIn account, post and new person (capped by `--max-credits`, default 150); X API ~$0.005 per post and reply plus ~$0.01 per author (reply reads capped by `--max-replies`, default 100; X spend capped by `--max-x-usd`, default 8); Exa about $0.04 per LinkedIn title and $0.07 per X match (capped by `--max-exa-usd`, default 3) |
| `pnpm apple-ads sync` | Pull campaigns, keywords and daily numbers from Apple | DB write; ad account read-only | `apple_ads_campaigns`, `apple_ads_keywords`, `apple_ads_keyword_daily`, `apple_ads_search_terms_daily`, `apple_ads_term_popularity`, `scrape_runs` | ~40 calls for `--all --days 1`; +1–2 calls per new keyword text, max 10/run |
| `pnpm apple-ads research` | Apple's keyword suggestions for the app | DB write unless `--no-save`; read-only | `apple_ads_term_popularity` | varies (one lookup per term; see --help) |
| `pnpm meta-ads sync` | Pull campaigns, ad sets, ads and daily numbers into the DB | DB write; ad account read-only | `meta_ads_campaigns`, `meta_ads_adsets`, `meta_ads_ads`, `meta_ads_creatives`, `meta_ads_ad_daily`, `meta_ads_ad_daily_breakdowns`, `meta_ads_changes` (journal), `scrape_runs` | varies (one page per object type + per-day insights; see --help) |
| `pnpm meta-ads status` | Show latest sync, counts, last-7-day metrics, creative tags | DB read | `meta_ads_*`, `scrape_runs`, `meta_ads_changes` | 0 |
| `pnpm meta-ads tag` | Merge manual attributes into a creative | DB write | `meta_ads_creatives` | 0 |
| `pnpm meta-ads media` | Download each creative's video/image, or import a file | DB write + media storage | `creatives`, `meta_ads_creatives`, `meta_ads_changes` (journal) | varies (one per creative; --creative/--file = 0) |
| `pnpm meta-ads pause` | Pause ads | Ad account write | `meta_ads_changes` (journal), `meta_ads_ads` | 1 read + 1 write per ad |
| `pnpm meta-ads activate` | Activate ads / ad sets | Ad account write | `meta_ads_changes` (journal), `meta_ads_ads`, `meta_ads_adsets` | 1 read + 1 write per object |
| `pnpm meta-ads adset-update` | Update an ad set's name / daily_min_spend_target / daily_budget | Ad account write | `meta_ads_changes` (journal) | 1 read + 1 write |
| `pnpm meta-ads adset-copy` | Copy an ad set into its campaign without its ads (PAUSED), then name it and set its daily budget | Ad account write | `meta_ads_changes` (journal) | 2 reads + 2 writes |
| `pnpm meta-ads create-ad` | Upload media and create a PAUSED ad from a template | Ad account write | `meta_ads_changes` (journal) | varies (upload polls; see --help) |
| `pnpm meta-ads ad-text` | Swap an ad's headlines/primary text via a rebuilt creative | Ad account write | `meta_ads_changes` (journal) | ~3 calls |
| `pnpm meta-ads launch` | Batch create PAUSED → activate → DB mirror from a spec of at most 10 ads | Ad account write | `meta_ads_changes` (journal), `meta_ads_adsets`, `meta_ads_ads`, `meta_ads_creatives`, `creatives` | 2 + ~11 Graph calls per video file (~5 per `video_id`, 4 per `image_hash`); ceiling 10 + 12 per ad (130 for 10) |
| `pnpm meta-ads verify` | Re-read the objects a plan document's writes touched and compare | DB read + ad account read | `meta_ads_changes` (read + journal rows only) | ≤6 GETs (typically 2: ads + ad sets) |
| `pnpm creatives profile` | LLM breakdown of each stored media file; runs daily from the daily review (`--source library --min-days 7 --limit 50`, then `--source favorites` for every starred ad and post) | DB write | `creative_profiles`, `creatives` | 1 Gemini Flash call per new file; already-profiled files and ads under `--min-days` cost nothing; `--limit` caps a run |
| `pnpm creatives angles` | Re-tag `strategy.angle` on stored profiles | DB write with `--apply` | `creative_profiles` | varies (LLM; --out alone = reads only) |
| `pnpm creatives show` | Print one stored profile | DB read | `creative_profiles` | 0 |
| `pnpm revenuecat sync` | Pull trials, conversions, revenue, proceeds per day/keyword | DB write | `revenuecat_keyword_daily`, `scrape_runs` | varies (see --help) |
| `pnpm scorecard` | Monthly profit vs goal from synced tables | DB read | `product_goals`, `revenuecat_keyword_daily`, `meta_ads_ad_daily`, `apple_ads_keyword_daily` | 0 |
| `pnpm scorecard goal` | Set a product's monthly profit goal | DB write | `product_goals` | 0 |
| `pnpm brief` | Goal, projection, last-N-days per channel, follow-ups due, stale data | DB read | same as scorecard + `experiments`, `experiment_log`, `experiment_campaigns`, `apple_ads_campaigns`, `apple_ads_keywords`, `social_posts`, `scrape_runs` | 0 |
| `pnpm experiment upsert` / `list` / `log --due` / `resolve` / `history` | Experiment records, dated log and follow-ups | DB read/write | `experiments`, `experiment_campaigns`, `experiment_log` | 0 |
| `pnpm mcp-key create [--scope read\|research]` / `list` / `revoke` | Per-agent keys for `/api/mcp` (only the SHA-256 is stored); `research` keys may also add sources and star items | DB read/write | `mcp_api_keys` | 0 |
| `pnpm doctor` | Which integrations have keys here (names only), what each missing one turns on, database reachable | env read + DB read | `products` (count) | 0 |
| `pnpm ready` | Local gate: format, typecheck, tests, db types, web typecheck, diff rules, privacy check and goal | repo checks + private-term sources | `products`, `tracked_sources` (privacy reads only) | 0 |
| `pnpm format` / `pnpm format:check` | Biome formatting (formatter only; no linter) | repo files | — | 0 |
| `pnpm privacy [--all]` | Block private terms in changed files (or all tracked files), paths, commit messages, branch names and PR text | DB/local/CI terms + git metadata | `products`, `tracked_sources`, `experiment_campaigns`, `apple_ads_keywords` (read-only) | 0 |

## Web pages (`web/app`, server components; Supabase service-role reads unless noted)

Product tabs keep data in a browser React Query cache per product and tab, fetched from `/api/p/[slug]/[tab]`; revisiting a tab shows its cached data while it refreshes. Heavy server data stays cached for 60 seconds with stale-while-revalidate, and server-action writes invalidate the product tag.

| Route | What it shows | Reads/writes | Tables touched | External API cost per run |
|---|---|---|---|---|
| `/` | Product list | DB read | `products` | 0 |
| `/setup` | Which keys this server has (names only) and how to add the rest; every page shows it while Supabase or sign-in is missing | env read | none | 0 |
| `/p/[slug]` | Goal-first overview (same numbers as `pnpm brief`), plus the last four weeks of spend/proceeds, presenter mode (`?present=1`) and an Apple ads switch, off by default (`?apple=on` turns it on), that leaves Apple's spend and RevenueCat-attributed customers out of every number. A product with B2B Social sources and no paid channel gets a lead-goal overview instead: qualified (fit A or B) leads this month with their pace, the funnel and the top leads | DB read | same as `pnpm brief`, including `apple_ads_keywords` and `experiment_campaigns`, plus `tracked_sources` and the `b2b_` tables | 0 |
| `/p/[slug]/ads` | Ad Library ads for the product, filterable by direct competitor vs adjacent niche, working / early signal, one Insights dimension (`by` + `v`) and favorites; star an ad; the preview shows the video transcript from its creative profile + add-source and relation-switch actions | DB read/write (source add, `config.relation`, `favorites`) | `ads`, `product_ads`, `scrape_runs`, `ad_library_observations`, `creatives`, `creative_profiles`, `favorites`, `tracked_sources` | 0; 1 Gemini Flash call per Transcribe click (about half a cent) |
| `/p/[slug]/ads/[id]` | One ad's detail and creatives | DB read | `ads`, `ad_creatives`, `creatives`, `ad_library_observations` | 0 |
| `/p/[slug]/apple-ads` | Apple Ads overview: campaigns, bids, experiments | DB read | `apple_ads_campaigns`, `apple_ads_keywords`, `apple_ads_keyword_daily`, `apple_ads_search_terms_daily`, `revenuecat_keyword_daily`, `experiments`, `experiment_campaigns`, `experiment_log` | 0 |
| `/p/[slug]/apple-keywords` | Keyword performance + term popularity | DB read | `apple_ads_keywords`, `apple_ads_keyword_daily`, `apple_ads_campaigns`, `apple_ads_term_popularity` | 0 |
| `/p/[slug]/brand` | Product profile, brand and research docs, tracked sources | DB read | `products`, `product_docs` (brand/research), `tracked_sources` | 0 |
| `/p/[slug]/insights` | Competitor insights: per angle, persona, hook type, format or landing page, ads, working ads and who they come from, all time or the last 14 days, as totals or by advertiser; every count opens the matching Competitor ads | DB read | `ads`, `product_ads`, `ad_creatives`, `creatives`, `creative_profiles`, `scrape_runs`, `ad_library_observations`, `tracked_sources` | 0 |
| `/p/[slug]/creatives` | Stored creatives grouped with profiles; ours, direct competitors or adjacent niches; competitor run-length filters (30+ / 90+ days, stopped fast, live) | DB read | `creatives`, `creative_profiles`, `product_ads`, `tracked_sources`, `meta_ads_creatives`, `meta_ads_ads` | 0 |
| `/p/[slug]/edit` | Edit product profile fields | DB write | `products` | 0 |
| `/p/[slug]/meta-ads` | Own Meta account overview | DB read | `meta_ads_campaigns`, `meta_ads_adsets`, `meta_ads_ads`, `meta_ads_creatives`, `meta_ads_ad_daily`, `meta_ads_ad_daily_breakdowns`, `scrape_runs` | 0 |
| `/p/[slug]/meta-ads/creatives` | Meta creatives with manual attributes | DB read | `meta_ads_creatives`, `meta_ads_ads`, `creatives` | 0 |
| `/p/[slug]/my-accounts` | Own social accounts' reels/videos (starrable, with transcripts in the preview and a Transcribe button) + add-source action | DB read/write (source add, `favorites`, `social_posts.transcript`) | `social_accounts`, `social_posts`, `social_post_snapshots`, `social_post_media`, `social_account_snapshots`, `creatives`, `creative_profiles`, `favorites`, `tracked_sources` | 0; 1 Gemini Flash call per Transcribe click (about half a cent) |
| `/p/[slug]/organic` | Competitor/inspiration accounts; newest first by default; star a post and filter to favorites; the preview shows the transcript (the post's own, else its video's creative profile), or a Transcribe button | DB read/write (source add, `favorites`, `social_posts.transcript`) | `social_accounts`, `social_posts`, `social_post_snapshots`, `social_post_media`, `social_account_snapshots`, `creatives`, `creative_profiles`, `favorites`, `tracked_sources` | 0; 1 Gemini Flash call per Transcribe click (about half a cent) |
| `/p/[slug]/b2b-social` | B2B Social: people who replied on X or commented on LinkedIn under the product's, its team's or competitors' posts and are worth a message, with a reason, their words, who they are (title, company, Fortune 500 / 10k+ / YC tag) and a suggested opener. A how-it-works strip, the watched accounts (click one to filter), filters for window, reason, company size, level, source and search, a person panel, and a CSV export for Clay. Secondary tabs: content reach on X and on LinkedIn. Plan: `docs/B2B_SOCIAL_MVP.md` | DB read | `tracked_sources` (source `b2b_social`), `b2b_posts`, `b2b_comments`, `b2b_people` | 0 (filled by `pnpm b2b-social sync`) |

| `/login`, `/api/auth/github`, `/api/auth/callback`, `/api/auth/logout` | GitHub sign-in for allowlisted owners; signed session cookie | none (cookie only) | none | 2 GitHub calls per sign-in |
| `/api/mcp` | MCP server for agents (per-agent bearer key): brief, experiments, own channels, competitor ads, organic posts, creative profiles, tracked sources, `product_docs`; `research`-scoped keys also get `track_ad_library`, `track_social_account` (competitor/inspiration) `favorite` and `save_url` (one ad/post by link, stored and starred without following) | DB read (+ `last_used_at`) + file read; research keys write `tracked_sources` and `favorites`, and `save_url` writes `ads`/`product_ads` or `social_accounts`/`social_posts`/`social_post_snapshots`, media to R2, and a `scrape_runs` row (`mcp_save`) | `mcp_api_keys`, `product_docs`, same as `pnpm brief`, `/p/[slug]/apple-ads`, `/p/[slug]/meta-ads`, `/p/[slug]/ads`, `/p/[slug]/organic`, `apple_ads_changes`, `meta_ads_changes`, `tracked_sources`, `favorites` | 0, except `save_url`: ~1 ScrapeCreators credit per new item, capped at 20 a day per key (new sources are fetched by the next daily sync) |

Every route except the sign-in flow and `/api/mcp` requires a signed-in owner (`web/proxy.ts`); server actions also
call `requireOwner()`. While sign-in is not configured, page loads show `/setup` and nothing else.

No web page or read-only command touches an ad account. Source add/remove actions on the ads
and organic pages write `tracked_sources` only.
